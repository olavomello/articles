If I Were Rebuilding Netflix's Engineering Org With AI

Scene 01 • Introduction

If I Were Rebuilding Netflix's Engineering Org With AI

A practical proposal for an AI Native engineering organization.

"How can we give great engineers an engineering system capable of multiplying their capabilities?"
  • This is not a description of Netflix's actual internal architecture — it's a thought experiment using technologies and practices available today.
  • The interesting part is not AI replacing engineers.
  • It's what happens when human engineering decisions become the input to a highly orchestrated network of AI agents, platforms, automation, and production systems.
Scene 02 • Human Decision

It Starts With a Human Decision

"Improve personalized recommendations for users watching content on mobile devices."

HUMAN → Product Intent → Specification ↓ AI Orchestrator ↓ Product Agent · Architecture Agent · Data Agent ↓ Engineering Agents ↓ Backend · Mobile · ML Agent ↓ Validation → HUMAN REVIEW
  • The human defines what and why.
  • The AI system helps determine how and in what sequence.
  • That distinction is fundamental.
Scene 03 • The Stack

The Proposed AI Engineering Stack

Six layers, from human decisions down to production.

HUMAN DECISIONS ↓ AI ORCHESTRATION ↓ AI ENGINEERING ↓ ENGINEERING PLATFORM ↓ CLOUD & DATA ↓ PRODUCTION
  • AI sits between human intent and engineering execution.
  • It doesn't replace the entire architecture — it operates within it.
  • Humans define the architecture and technology boundaries; agents operate inside those boundaries.
Scene 04 • Context & Tools

Context Engineering & MCP

RAG feeds the agent context. MCP exposes controlled tools instead of unrestricted access.

get_repository() create_branch() run_tests() analyze_logs() get_metrics() create_pull_request() deploy_staging() rollback()
  • An AI agent cannot make good engineering decisions without good context — a RAG layer retrieves architecture docs, API contracts, standards, and prior decisions.
  • Files like AGENTS.md become part of the operational context given to AI agents, not just documentation for developers.
  • The agent becomes capable of acting, but the platform still controls what it is allowed to do.
Scene 05 • Specialized Agents

Specialized Agents, Not One Giant AI

This is much closer to an engineering organization than to a chatbot.

ORCHESTRATOR ↓ Architecture · Coding · Data Agents ↓ Security · Testing · ML Engineering Agents ↓ Performance Agent → Review Agent
  • Each agent has a responsibility: architecture analysis, implementation, testing, security, performance, data, and final review.
  • I would not create one giant "Netflix AI Engineer" — I would create specialized agents.
Scene 06 • Safety Layer

GitHub, CI/CD & the Platform as Safety Layer

The platform evaluates and authorizes before any infrastructure action executes.

AI Agent → Git branch → Implementation → Automated tests → Pull Request → AI review → Security analysis → Human review → Merge
  • GitHub remains the collaboration layer — AI simply becomes another participant in the workflow.
  • CI/CD becomes an AI validation loop: if a build fails, an agent analyzes logs, identifies a probable cause, and proposes a fix.
  • Agents should interact with capabilities, not necessarily with unrestricted infrastructure — the platform checks authorization, environment, resource limits, and security policy first.
Scene 07 • Control Plane

The Control Plane & Incident Response

Human control scales with risk.

"The higher the potential impact, the stronger the human control."
  • With AI, an incident flows through: Alert → Incident Agent → correlate logs, metrics, traces, deployments, and recent commits → root cause analysis → recommended action → human decision.
  • For low risk operations, some actions could become automated; for high risk operations, human approval remains mandatory.
  • AI becomes a kind of engineering control plane, creating a continuous loop between production, observability, and human feedback.
Scene 08 • Conclusion

Using AI to Code vs. Engineering With AI

The more autonomous the agents become, the more important engineering expertise becomes.

"Give Netflix's engineers an AI Native engineering system capable of building, operating, and continuously improving Netflix at a scale that was previously impossible."
  • The goal isn't "let AI build Netflix" — it's giving engineers an AI Native system to build, operate, and improve at a scale previously impossible.
  • AI can produce an answer; the engineer needs to determine whether that answer is good enough to become part of reality.
  • That is the difference between using AI to code and engineering with AI — and it will define one of the most important transitions in software engineering over the next decade.
