From Teams to Agents
Scene 1 of 8
Scene 01 • Introduction

From Teams to Agents

The changing economics of software engineering.

"We are learning how to multiply the capabilities of software engineers."
  • Not "AI is replacing software engineers" — a more interesting story is unfolding.
  • The more powerful our tools become, the more important the people who use, design, orchestrate, and govern them become.
  • AI agents can now write code, create tests, analyze repositories, and work on multiple tasks simultaneously.
Scene 02 • Yesterday's Team

The Software Team of Yesterday

Building a professional SaaS product used to require a full team, in sequence.

Product Manager ↓ UX / UI Designer ↓ Software Architect ↓ Frontend / Backend Engineers ↓ Database Engineer ↓ QA → DevOps → Security ↓ Production
  • Every stage had dependencies — a backend change could require a frontend change, a database change could require migration work.
  • The bigger the team became, the more coordination was required.
  • The limiting factor was often the capacity to coordinate many specialized people, not individual engineer ability.
Scene 03 • A New Participant

AI Agents Enter the Workflow

The engineer can now delegate far more than a single function.

"Analyze this repository, understand the architecture, implement the feature, create the tests, update the documentation, run the test suite, identify failures, and prepare the changes for review."
  • The AI is no longer just autocomplete — it is becoming an engineering participant.
  • Engineer → AI Orchestrator → Coding Agent / Testing Agent / Review Agent, each feeding into CI/CD.
  • The engineer is designing and controlling the system that produces the software.
Scene 04 • The New Bottleneck

From Sequential to Parallel Work

AI agents introduce the possibility of much greater parallelization — but that creates a new constraint.

Business Intent → Specification → Task Decomposition → Agent Assignment → Parallel Execution → Validation → Integration → CI/CD → Production → Observability → Feedback ↺
  • Parallel execution without good orchestration can create chaos faster — ten agents on the wrong plan produce ten times more problems.
  • The intelligence is not only inside the models — it is inside the system surrounding them.
Scene 05 • Foundation

Expertise Becomes Leverage

Effective orchestration comes from understanding software, not from knowing how to open a chat window.

  • A strong engineer's knowledge — architecture, distributed systems, databases, security, testing, infrastructure — becomes the foundation for effective AI orchestration.
  • Without it, the engineer may simply generate more code. With it, the engineer can generate better systems.
  • An engineer who understands payment architecture and fraud prevention can give the AI far better constraints — and recognize when it generates something dangerous.
"AI assisted coding" versus "AI assisted engineering" — the second requires significantly more expertise.
Scene 06 • The New Role

The Engineer Becomes an Orchestrator

Designer + Architect + Orchestrator + Reviewer + Decision Maker.

"AI agents should not necessarily receive unrestricted access to infrastructure. They should interact with well designed capabilities and boundaries."
  • The engineer defines the problem; AI explores the solution space; agents execute specialized tasks; the engineer makes the final decisions.
  • Platform Engineering becomes the controlled execution environment for both humans and AI — infrastructure, security, and observability exposed as boundaries.
  • When code becomes cheaper to produce, architecture becomes increasingly valuable — generating the wrong 10,000 lines becomes just as easy.
Scene 07 • New Economics

The New Economics of Software

The competitive advantage may come from the best engineering system, not the largest team.

12 engineers, 6 months ↓ (a different model) 3 experienced engineers + AI orchestration + specialized agents + automated testing + CI/CD + platform engineering
  • The important point isn't the exact headcount — it's the change in leverage.
  • A highly capable engineer may control a much larger software production system than before.
  • Human expertise + AI intelligence + agent specialization + platform engineering + automation + validation + observability, working together.
Scene 08 • Conclusion

The Human Remains in the Loop

The more autonomous the system becomes, the more important governance becomes.

"Perhaps the most valuable engineer of the future will not be the one who writes the most code. It will be the one who can orchestrate the most capable engineering system, while still knowing exactly when to trust it, when to question it, and when to take control."
  • Agents can generate, analyze, test, review, and deploy — but someone still needs to own the outcome, especially for security, financial systems, healthcare, and compliance.
  • The future may not be fewer engineers — it may be fewer engineers on repetitive work, and more on higher-leverage work: thinking, designing, architecting, validating.
